# 静默规则首呼预演（FastAPI + Docker Compose）

值班员在**新增静默规则之前**预演：哪些故障轮次的**首呼会被推迟**、哪些**可能收不到首呼**，
并逐轮给出加静默前后的首呼时刻与**随呼叫发出的未静默活动告警**快照。

## 计时与判定口径

1. **告警**：`fired_at` 触发，`recovered_at` 恢复（可留空 = 截至观察截止仍未恢复），活动区间为右开 `[fired_at, recovered_at)`。
2. **静默规则**：`start_at` 生效、`end_at` 解除（右开）；规则为**全标签匹配**——告警标签包含规则列出的**全部**标签条件才被屏蔽；命中任一现行/拟议规则即被屏蔽。
3. **故障轮次（同服务）**：后一条告警在前一条仍活动时触发则并入同一轮；轮次直到该服务参与轮次的告警**全部恢复**才结束。静默不结束轮次，只暂停计时。
4. **首呼等待**：同一服务只要一直存在**未被静默的活动告警**，等待就连续计时（告警换了也一样）；未静默告警断档后重新出现，则**重新等待一个完整时长**。
5. **同刻变化**：触发/恢复/静默生效/解除落在同一时刻时，先一并应用再判定计时与首呼。
6. **每轮只首呼一次**；首呼时刻必须**严格早于**观察截止（恰好落在截止点不呼叫），截止时仍在等待的轮次明确标注“截至观察结束仍未首呼”。
7. 两套模拟（现行规则 / 现行+拟议规则）共用同一套由告警推导的轮次，逐轮对照。

## 运行方式

### Docker Compose（推荐）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

页面打开即自动载入样例，直接点“运行预演”即可；也可把告警 JSON 保存为文件后通过页面导入。

### 本地直接运行（无 Docker 时）

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 自测

```bash
pip install -r requirements.txt
python -m pytest tests/ -q
```

## 页面与接口

- `GET /`：预演页（告警导入、两套静默规则、等待时长、观察截止、逐轮对照表）
- `POST /api/simulate`：请求体同页面结构，返回汇总计数与逐轮对照（含每段未静默活动区间，便于核对计时过程）
- `GET /api/sample`：返回内置样例载荷

请求字段：

| 字段 | 说明 |
| --- | --- |
| `alerts[]` | `id` / `service` / `labels{}` / `fired_at` / `recovered_at`(可 null) |
| `current_silences[]` | 现行规则：`id` / `labels{}` / `start_at` / `end_at` |
| `proposed_silences[]` | 拟新增规则，结构同上 |
| `wait_minutes` | 首呼等待时长（分钟，>0） |
| `cutoff_at` | 观察截止时间 |

时间统一用 ISO-8601，推荐带 `Z`（如 `2026-11-21T10:00:00Z`）；不带时区的时间按 UTC 处理。
截止之后才触发的告警会被忽略并在响应中列出。

## 内置样例（等待 10 分钟，截止 2026-11-21 12:00 UTC）

| 服务 / 轮次 | 判定 | 加前首呼 | 加后首呼 | 说明 |
| --- | --- | --- | --- | --- |
| payment-api #1 | 推迟 +10 分钟 | 10:10（A1+A2） | 10:20（仅 A2） | S1 在 10:05–10:15 屏蔽 A1；10:10 A2 触发后计时重新起步，随呼快照只剩未静默的 A2 |
| order-db #1 | 收不到首呼 | 10:40（A3） | 未首呼 | S2 按 `service=order-db` 全程屏蔽，且 A3 未恢复、轮次未结束 |
| cache #1 | 推迟 +15 分钟 | 10:30 | 10:45 | S3（10:25–10:35）造成断档，解除后重新等满 10 分钟 |
| cache #2 | 前后均未首呼 | — | — | 告警只活 5 分钟，短于等待时长 |
| auth #1 | 收不到首呼（截止仍在等待） | 11:25 | 未首呼 | S5 屏蔽至 11:55，重新计时后 12:05 才满足，晚于截止 |
| gateway #1 | 无变化 | 11:10 | 11:10 | S4 窗口在告警恢复之后，完全不影响 |
| test-svc #1 | 前后均未首呼 | — | — | 现行 R1（`env=test`）已全程屏蔽，两套模拟一致 |

汇总：7 轮中加静默前 5 轮首呼、加后仅 3 轮；推迟 2 轮、被压掉 2 轮、不变 1 轮、前后均未首呼 2 轮。
